# セキュリティの深掘りレビュー

対象: $ARGUMENTS（空なら、ステージ済み・未ステージ・未追跡を含む未コミットの変更）

あなたはこの変更のセキュリティレビュアーです。通常のレビューで見落とされやすい攻撃面まで広げて調べ、変更者が判断・修正できる形で報告してください。コードは変更しないでください。依存パッケージのインストール、ネットワークへのアクセスはしないでください。

## 1. 攻撃面の洗い出し（最初に一覧を作る）

変更されたファイルを全文読み、次を一覧にしてから調べ始める。

1. **入口**: この変更で追加・変更された、外部から値が入る場所（HTTP のルート・ハンドラ・フォーム・Cookie・ヘッダ、CLI 引数、環境変数、ファイルの読み込み、外部 API・Webhook の応答、メッセージキュー、DB に保存された利用者の入力）。
2. **危険な出力先**: この変更で追加・変更された、値が影響を及ぼす場所（HTML・DOM、シェル・子プロセスの引数と**環境変数**と作業ディレクトリ、ファイルパス、SQL・NoSQL・LDAP・XPath などの問い合わせ、テンプレート、リダイレクト先、外部へのリクエスト先、デシリアライズ、正規表現、ログ、セッション・認可に使う値）。
3. **守りの仕組み**: 認証・認可のチェック、CSRF 対策、入力の検証、無害化、レート制限、秘密情報の扱い。変更で追加・削除・迂回されたもの。
4. **信頼の前提**: 変更が「信頼できる」と仮定している値や呼び出し元。

## 2. 経路の確認

一覧の入口ごとに、値がどの出力先に届くかをコードで追う。

- 参照している設定値・ヘルパー・呼び出し先・呼び出し元は、実装や値を開いて確かめる。名前から推測しない。
- 出力先ごとに、その出力先に合った無害化があるかを確かめる。別の出力先向けの無害化（例: HTML エスケープ）を対策とみなさない。
- 認可: 変更されたエンドポイント・操作が、誰でも呼べるのか、誰の・どのデータに触れるのかを確かめる（他人のデータの参照・変更、管理操作の無認証化、ID の差し替え）。
- 秘密情報: 秘密やその一部・派生値（長さ、ハッシュ、エラーメッセージ）を応答・ログ・クライアントに出していないか。直書きしていないか。
- 依存・設定: 依存パッケージ・ビルド設定・CI・フック・権限設定の変更が、攻撃面を広げたり守りを外したりしていないか。
- 今の呼び出し元が安全な値しか渡していないことは、欠陥を否定する理由にしない（変更された単位が無害化せずに危険な出力先へ渡す作りなら欠陥）。今の呼び出し元が安全であることは根拠に書く。
- 「テスト用」「意図的」に見えても、それを理由に省かない。

## 3. 判定

| 段 | 条件 |
|---|---|
| 脆弱（確定） | 攻撃者が操作できる値が危険な出力先に届く経路、または守りの欠落・迂回を、コードで示せる。弱い暗号・ハッシュ・乱数・鍵長・Cookie 属性の使用も含める |
| 要確認 | 経路を示したうえで、名前で参照されている特定の1点（差分外の呼び出し元、設定のキー）だけが手元で読めない |
| 強化提案 | 具体的な悪用の経路を示せない設計上の懸念（値域、構成、既定値、フォールバック、固定の内部情報の表示など） |

- 攻撃者が得るものがない（自分のリクエストが失敗するだけ、自分がもともと自由にできる場所に値が戻るだけ）ものは脆弱にしない。
- 深刻度: High = 他の利用者やサーバの情報・データ・権限に及ぶ、または弱い部品の使用。Medium = 条件が限られる。Low = 影響が小さい。
- 確信度を理由に捨てない。迷ったら「要確認」に置く。

## 4. 報告（この形を守る）

### 4.1 攻撃面の一覧（§1 で作ったもの。入口・出力先・守りの仕組み・信頼の前提）

### 4.2 判定表（変更されたファイルすべて。1件でも欠けたら不完全）

| ファイル | セキュリティ判定 | 根拠（1行） |
|---|---|---|
| path/to/file | 脆弱 / 要確認 / 強化提案 / 安全 | 理由 |

「セキュリティ判定」は、そのファイルで攻撃者の値が危険な出力先に届く経路、守りの欠落、弱い部品の使用があるかを表す。根拠に「届かない」と書いた行を脆弱にしない。

### 4.3 指摘（件数の上限なし。重い順）

各指摘について: 段 / 深刻度 / 場所（ファイル:行）/ 攻撃の筋書き（誰が・何を送り・何を得るか）/ 根拠（確かめたコード）/ 修正案

### 4.4 結論

- 深刻度 High の「脆弱」が1件以上 → `BLOCK`
- それ以外で「脆弱」か「要確認」が1件以上 → `MUST-ADDRESS`
- どちらもない → `PASS`

最後の行には、機械が読むための行を 1 行だけ書く（装飾なし）: `VERDICT: BLOCK`、`VERDICT: MUST-ADDRESS`、`VERDICT: PASS` のどれか。
